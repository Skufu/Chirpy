# Chirpy Server

A Go HTTP server serving static files, providing a Chirp API, and tracking usage metrics.

## Overview

Chirpy Server provides:
- Static file serving from the `/app` endpoint
- A simple Chirp API (create users, create chirps)
- Health check endpoint
- Request metrics tracking
- Database reset functionality (dev environment only)

## Features

### Static File Serving

The server serves static files from the project's root directory through the `/app/*` endpoint. Each request to this endpoint increments a hit counter.

### Chirp API

- **Users:** Create new users.
- **Chirps:** Create new chirps associated with a user.

### API Endpoints

| Endpoint             | Method | Description                                                                 |
| -------------------- | ------ | --------------------------------------------------------------------------- |
| `GET /api/healthz`   | GET    | Health check endpoint that returns "OK" when the server is running          |
| `POST /api/users`    | POST   | Creates a new user account                                                  |
| `POST /api/chirps`   | POST   | Creates a new chirp                                                         |
| `GET /admin/metrics` | GET    | Returns the number of hits to the static file server in HTML format         |
| `POST /admin/reset`  | POST   | Resets hit counter and clears the database (requires `PLATFORM=dev`)        |
| `/app/*`             | GET    | Serves static files from the root directory                                 |

### Metrics Tracking

The server tracks the number of requests made to the static file server (`/app/*`) using atomic counters. Metrics are available at `GET /admin/metrics`.

## Technical Details

### Architecture

- Built with Go's standard `net/http` package.
- Uses PostgreSQL database for storing users and chirps.
- Database interactions managed via `sql` package and `internal/database` generated code.
- Uses atomic operations for thread-safe hit counter.
- Implements middleware for request counting.
- Uses `http.StripPrefix` for static file serving.
- Configuration managed via `.env` file (e.g., `DB_URL`, `PLATFORM`).

### Code Structure

- `main.go`: Server setup, routing, and handler implementations.
- `internal/database`: Database connection, queries, and models ( generated by sqlc).
- `apiConfig`: Struct holding server state (hit counter, database connection, platform).
- Handlers: Specific functions for each API endpoint (e.g., `handlerCreateUser`, `handlerCreateChirp`, `handlerMetrics`, `handlerReset`, `handlerReadiness`).
- Middleware: `middlewareMetricsInc` for counting hits.

## Running the Server

1.  **Create a `.env` file:**
    ```env
    DB_URL=postgresql://user:password@host:port/dbname?sslmode=disable
    PLATFORM=dev # or prod
    ```
    Replace connection details with your PostgreSQL setup.
2.  **Start the server:**
    ```bash
    go run .
    ```

The server will start on port 8080 by default. Access it at [http://localhost:8080](http://localhost:8080).

## Development

- Uses Go modules for dependency management.
- Requires a running PostgreSQL instance.
- Database schema (users, chirps tables) is created automatically on startup if it doesn't exist.
- The `/admin/reset` endpoint is useful for clearing data during development (requires `PLATFORM=dev`).
